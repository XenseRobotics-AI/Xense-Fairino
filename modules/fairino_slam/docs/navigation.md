# 全向预瞄点导航

导航使用自有 `StraightLinePlanner` 执行直线优先规划，绕障搜索复用 SmacPlanner2D，自有 `HolonomicLookaheadController` 跟随路径。Nav2 的 FollowPath/NavigateToPose、生命周期、取消和进度检查继续使用原接口。速度仍经过 `velocity_gate` 和底盘 Worker 的状态、超时及限速检查。

## 直线优先全局规划

开关位于 `config/navigation.yaml` 的 `nav2.planner_server.ros__parameters.GridBased.straight_line_enabled`，默认 `true`。设为 `false` 时直接返回原 SmacPlanner2D 的规划结果，不进行直达检查、捷径简化、重新采样或额外端点限制；原有 Smac 参数保留。修改后重新部署导航才在机器人端生效，不在活动任务中热切换。

开启时按以下流程规划：

1. 起点到目标的完整线段通过碰撞检查时，直接采用该直线。
2. 直达被挡住时，先用 SmacPlanner2D 找到绕障路径。相邻对角栅格之间若擦过禁行角点，仅在两个子段均安全时补一个轴向折点；否则拒绝该路径。然后从每个保留点寻找可以安全直达的最远后续点，合并多余拐点，尽量得到少量长直线段。
3. 按不大于地图分辨率的间隔重新采样，供现有预瞄控制器连续跟随；稠密采样点不会增加几何拐弯。保留请求的起终点和终点朝向。
4. 返回前使用更新的代价地图快照再次检查整条路径。地图更新后的安全性继续由全局重规划和局部扫掠碰撞检查负责。

检查使用包含静态地图和实时雷达障碍的全局代价地图。每条线段检查所有接触的栅格，禁止穿过代价 253/254/255、地图外或仅从禁行格角点擦过。障碍物使用现有轮廓膨胀后的代价，不缩小碰撞半径；未知区域与地图边界另按全局有效碰撞半径保护，避免只检查车体中心。该额外保守保护可能使靠近未知区的通路不可用。

直线优先不累计比较 1–252 的软代价，因此可能比原路径更接近障碍，但仍受硬碰撞留量约束。绕障搜索的 `cost_travel_multiplier=2.0` 和关闭的 Smac 平滑器保持原值；不保证全局最少折线或最优转弯半径。目标中心不满足新检查、Smac 路径无法安全衔接精确终点或规划预算耗尽时明确失败，不退回未经检查的路径。关闭开关时保留原 Smac 的容差行为。

优化不改变现有预瞄更新周期、连续速度输出或两种朝向策略。折线拐角仍可能需要底盘对轮；它减少路径中的无意义小折线，不能单独保证底盘始终不停顿。

源码与离线数值测试位于 `ros2/fairino_straight_planner/`。`GridBased.max_planning_time`（当前 2 秒）用于本插件的处理预算；按实际 Nav2 基类自动兼容两参数和三参数规划接口，不以 ROS 发行版名称判断。现场三参数接口会把取消回调传给 Smac，并在直线优化循环中检查取消；旧两参数接口无法中途传入取消。Smac 内部锁等待不能被包装层强制中断；搜索返回后若已超预算则拒绝结果。

## 参数入口

编辑 `config/navigation.yaml` 中 `nav2.controller_server.ros__parameters`：

| 参数 | 当前配置值 | 含义 |
|---|---|---|
| `controller_frequency` | 3.0 Hz | 读取位姿、选点、计算速度的周期 |
| `FollowPath.lookahead_distance` | 0.20 m | 当前位置到路径预瞄点的欧氏直线距离 |
| `FollowPath.heading_mode` | `hold_initial` | `hold_initial` 保持当前朝向；`path_tangent` 沿路径方向并使用输入的终点朝向 |
| `FollowPath.position_gain` | 0.8 /s | 位置误差到平移速度的比例增益 |
| `FollowPath.heading_gain` | 1.5 /s | 朝向误差到角速度的比例增益 |
| `FollowPath.projection_search_distance` | 1.0 m | 路径进度的局部向前搜索范围 |
| `FollowPath.collision_horizon` | 1.0 s | 碰撞预测时间下限，实际还覆盖制动时间 |
| `FollowPath.collision_step` | 0.05 s | 扫掠检测的最大步长，还按地图分辨率缩短 |

速度上限、加速度仍由 `config/chassis.yaml` 统一提供。当前平移 0.10 m/s、旋转 0.20 rad/s，平移加速度 0.20 m/s²、旋转加速度 0.40 rad/s²。控制周期、目标容差和共享限值由生成器注入插件，避免重复设置。

## 选点与朝向

每个周期先在路径前进方向确定当前进度，再求路径线段与以当前位置为圆心、配置的预瞄距离（当前 0.20 m）为半径的圆的交点，选第一个有效前向交点。线段之间插值；同一路径不会回退进度。重规划更换路径后重新关联路径进度，保留连续速度状态。

路径尾段没有圆交点时可使用终点。存在回绕、偏离路径过大或无有效前向点时停止并交由 Nav2 处理失败，不能为了选到点而跳到附近的后续路径段。

两种策略都在机器人端读取新鲜 `map → base_footprint` TF，核对定位会话、初始化时间、里程计 epoch 和导航进程。预览与实际发送分别检查；输入目标不会自动发起运动。

- `hold_initial`：行进阶段锁定启动时的当前 yaw；到达目标位置并停稳后，再转向填写的终点朝向。手动目标和保存点都支持终点朝向，界面用度、CLI 的 `--yaw` 用弧度。预览采样的启动朝向不会提前锁定下一次任务。CLI 省略 `--yaw` 时兼容保持启动朝向。
- `path_tangent`：沿途使用当前路径投影点到预瞄点的方向，退化时取有效前向线段。目标位置和朝向必须完整输入：界面使用度，CLI `--yaw` 使用弧度，均为 map 坐标系的绝对朝向（0° 沿 +X，90° 沿 +Y），不是相对车身的转角。进入有效终点尾段后，在预瞄距离到位置容差之间按最短角平滑过渡到输入朝向；进入位置容差后使用完整目标朝向，直到位置、朝向及停止速度均满足到达条件。单点路径可以原地转到目标朝向。

转向继续受角速度和角加速度限制，允许全向平移与转向同时进行；大角度变化可能需要到点后继续转向。重规划保留速度状态和用户目标朝向。`SmacPlanner2D.use_final_approach_orientation` 保持 `false`，以保留目标四元数，不能为了沿途朝向跟随而改成 `true`。

策略在 `config/navigation.yaml` 的 `nav2.controller_server.ros__parameters.FollowPath.heading_mode` 切换。目前默认仍为 `hold_initial`。要启用新策略，将值改为 `path_tangent`，结束导航后重新部署完整导航组件并重启电脑端面板。机器人按已部署配置执行；每次请求携带电脑端预期策略，不一致或旧机器人不支持时拒绝发送，不自动降级。

启用并部署 `path_tangent` 后，CLI 示例（目标朝向 90°）：

```bash
bash scripts/run.sh navigation plan --x 1 --y 0 --yaw 1.5707963267948966
bash scripts/run.sh navigation goal --x 1 --y 0 --yaw 1.5707963267948966
```

## 目标位姿到连续速度

预瞄点给出目标位置 `(x_t, y_t)`，所选朝向策略给出 `yaw_t`。控制核心先计算世界坐标的位置误差，并将朝向误差归一化到 `[-π, π]`：

```text
vx_world = position_gain × (x_t - x)
vy_world = position_gain × (y_t - y)
wz       = heading_gain × wrap(yaw_t - yaw)
```

对平移合速度和角速度限幅，再限制相邻周期平移速度向量及角速度的变化量。最后按当前车身朝向将世界速度旋转为车体系 `vx/vy`，输出 `Twist`。因此车辆可以侧向行进，同时用角速度修正偏航误差。

接近终点时按剩余制动距离限制速度。进入目标容差后，目标速度置零并按加速度减速；`StoppedGoalChecker` 等待实测速度低于平移 0.005 m/s、旋转 0.01 rad/s 后确认成功。取消、数据过期或碰撞保护则立即请求零速度。

代码分层：

- `ros2/fairino_lookahead_controller/include/fairino_lookahead_controller/core.hpp`：预瞄点与位姿到速度的纯 C++ 算法，可脱离 ROS 编译测试。
- `src/controller.cpp`（同一 ROS 包）：Nav2 插件、TF、局部代价地图、速度输出；发布 `/fairino_navigation/lookahead_target` 供 ROS 可视化检查。
- `include/fairino_lookahead_controller/collision.hpp`：足迹内部、未知区域、越界和扫掠碰撞检查。
- `src/fairino_slam/navigation/navigation_remote.py`：已部署策略核对、终点朝向确定及会话检查。

## 底盘停车对轮时的协调

导航底盘 Worker 发布 20 Hz 的 `/fairino_navigation/chassis_motion_state`，消息类型为 `diagnostic_msgs/msg/DiagnosticArray`。在硬件反馈新鲜、底盘正常使能且已有运动请求时，四个行走驱动器的速度指令同时为零，判为 `drive_wait`。这是从实际驱动器输出观察到的等待，不是直接读取厂商控制器的内部 `ALIGN_ONLY` 状态，也不能据此确定底层故障原因。

等待期间仍持续发送受限的小非零速度意图，让底层能够继续对轮；稳定目标下保持平移/旋转比例，导航速度斜坡不继续累积。只有请求方向明显改变时才更新该意图，原有 TF、定位、碰撞、雷达和超时检查继续生效。路径进度仍根据实际位姿更新，重规划不会重新开始等待计时。驱动器恢复输出后，跟随器用当前实测速度重新开始加速，避免把等待期间累积的高速度突然下发。

参数位于 `FollowPath`：`coordination_linear_speed=0.02` m/s、`coordination_angular_speed=0.04` rad/s 是等待意图上限；`coordination_direction_tolerance=0.20` rad 控制方向变化判定；`coordination_wait_timeout=15.0` s 限制连续等待时间。真正恢复驱动输出后才结束本次等待。等待时间须短于进展检查时限；协调速度须低于对应导航速度且大于底层运动请求的零值判定范围。硬件反馈超时直接沿用 `config/chassis.yaml` 的 `timeouts.feedback`，不在导航 YAML 重复设置。

速度门控使用独立节点、执行器和接收线程处理底盘运动反馈，并以 20 Hz 独立检查反馈年龄，避免主循环的 TF、文件或 graph 查询延迟阻塞接收。接收线程只更新受锁保护的反馈和首个故障记录，速度输出及目标取消仍在原控制线程串行执行；短暂故障、真正断流或 Worker 会话变化不会被后续正常样本覆盖。诊断同时记录消息年龄、源端硬件年龄、累计年龄和 0.4 秒门限。\n\n反馈缺失、无效、过期、未就绪、发布源不唯一或 Worker 会话变化都会保护停止当前目标；连续等待超时也停止。随后恢复健康数据不会自动恢复旧目标。已有驱动器故障仍按原流程处理，不通过自动重置或放宽故障门限继续运动。

## 避障与验证边界

控制器对最终速度和实测速度分别预测完整足迹扫掠，覆盖制动时间和一个控制周期的反应时间；障碍、未知区域和地图边界触发零速度暂停，并由行为树取消当前跟随、重新规划。过期地图/TF、底盘反馈故障等仍终止当前目标，不自动恢复。全局规划仍周期更新。

该跟随器不执行 DWB 的局部候选轨迹搜索。路径拐角与车体足迹不兼容时可能停止并需要重规划；保持固定车身朝向也会限制窄通道通过方式。底盘碰撞模型仍不包含上半身动态投影。

离线验证：

```bash
bash scripts/check_controller.sh  # 用 C++17 编译器运行同一份数值/碰撞核心
bash scripts/check.sh --package  # Python、C++ 核心、源码包、wheel 检查
```

规划重试的实际行为树语义测试位于 `tests/navigation/test_planning_retry.cpp`，使用 BehaviorTree.CPP v3 执行两棵部署 XML 和同一份 `ReplanUntilClear` 调度器，以模拟动作和时钟覆盖：首次即时规划、超过 80 次失败后的恢复、失败后停止旧路径、局部碰撞等待、跟随故障优先、取消及树复用。测试不创建 ROS 节点；ROS 适配器、实际 Action 取消和实车停车距离仍需独立联调。

完整 ROS 适配器与 pluginlib 加载测试分别位于两个 ROS 包的 `test/test_plugin.cpp`；CI 单独配置 Humble 容器执行。没有 ROS 的电脑只能验证独立 C++ 核心和 Python 层，不能把这些结果视为 ROS 插件或实车验证通过。

## 输入接收与状态提示

导航的雷达、里程计、AMCL 位姿、原始速度与行为树执行状态，由独立接收节点处理；主线程读取文件、查询 ROS graph 或检查 TF 时，接收回调继续更新。控制目标和速度输出仍由主线程管理。输出前在短锁内重新检查最新暂停/故障和指令年龄，避免并发收到停止状态后仍发布先前算出的速度。地图页面也独立接收传感器和 TF，绘图及 SSH 输出不会暂停接收。

“定位正常，可导航；当前运动量未达到下一次雷达匹配阈值”是正常状态，AMCL 仍按原有运动门槛更新。真正输入过期时，页面指出融合雷达或里程计及数据年龄。双雷达 0.5 秒、定位输入 0.75 秒、导航执行/速度 0.6 秒的门限保持不变；接收线程故障、无新数据或保护失败不会通过后台心跳伪装成健康。保护事件记录最新执行状态和输入接收线程状态，便于区分源端中断和接收延迟。

## 请求等待与持续重规划

TF 年龄门限由 `src/fairino_slam/navigation/runtime_policy.py` 的 `TF_MAX_AGE` 统一提供，当前为 1.0 秒（严格小于）。门控诊断、预览和发送目标前的朝向检查使用同一值；朝向采样对未来时间戳仍只允许 0.05 秒偏差。速度指令断流门限由同一文件的 `COMMAND_TIMEOUT` 定义，当前为 0.6 秒；超过门限会停止并锁定当前目标。双雷达门限为 0.5 秒。

预览和发送目标使用独立的 TF 接收节点与线程，并在同一次请求的预览重试间复用；服务查询、配置读取不会暂停 TF 接收。阻塞检查完成后重新读取最新位姿，再按当前时钟验证。Action 回调仍在命令节点串行处理，结束请求时显式关闭接收线程。

发送请求前，明确的 TF 缺失或过期可在同一个 3 秒窗口内等待恢复。地图、初始位姿、里程计 epoch、导航进程或保护状态发生变化时立即结束等待；时钟异常、非法数据、已有活动目标和其他未就绪状态不自动绕过。旧目标的历史保护记录不会永久阻止用户发起一个新的显式目标。

路径预览仅在收到规划动作明确的 `ABORTED` 最终结果后重试，最多共 3 次，间隔 0.5 秒；每次重新检查同一会话并获取新鲜朝向。预览规划部分的总等待预算为 40 秒，异常后取消清理最多另等 3 秒。目标拒绝、取消、未知状态、空路径、发送确认或结果超时不会触发重发。`NavigateToPose` 运动目标每次调用最多发送一次，结果不明确时由状态查询确认。

行驶中的行为树位于 `config/behavior_trees/`，使用 `fairino_replan_bt_node` 的 `ReplanUntilClear` 节点：首次立即规划；规划失败后保持原目标，每次失败结束后等待 **1 秒** 再试，不限制次数。正常跟随时每 1 秒进行一次全局更新。规划计算时间另计，不并发堆积请求；每次仍受规划器自身的 `max_planning_time` 约束。路径预览的三次上限不变。

规划失败会立即暂停输出、取消旧的 FollowPath；没有新成功路径时不再跟随旧路径。局部碰撞检查触发时，控制器先输出零速度并上报原因，行为树取消跟随后进入同一等待流程。等待不占用 FollowPath 的进展计时，因此人持续站在路径上不会仅因三次失败或进展超时而丢失目标。未知区域和地图边界也可能触发等待；无法确认是行人时，界面不会将其归因为行人。

规划成功后重新发起跟随，仍需通过最新局部足迹扫掠、TF 和底盘反馈检查。旧速度指令在暂停和恢复切换时丢弃，跟随器重置速度历史，从实测速度按原加速度限制恢复。新路径仍被局部障碍阻挡时再次输出零速度并等待，不绕过碰撞检查。

执行状态通过 `/fairino_navigation/execution_state/navigate_to_pose` 送到速度门控，随 `status.json` 的 `execution` 字段传到控制页面；界面优先显示暂停/失败原因，再显示一般就绪状态。暂停期间只有来源正确、时间新鲜的行为树心跳才能维持等待；状态断流、速度来源异常、定位/雷达/底盘故障及会话变化仍锁定停止当前目标，故障恢复不会自动启动旧目标。控制器内部失败与 Action 跟随失败仍终止导航。

点击“取消目标”或“结束导航并下使能”会取消等待和未完成的规划/跟随动作，障碍移除后也不会自动启动。需要再次显式发送目标。更新必须完整重新部署导航（BT 动态库、控制器、行为树、门控与配置一起更新），并重启控制页面；只替换 XML 不足以生效。部署程序会先构建并加载检查 BT 动态库，再切换运行文件；部署本身不使能或启动机器人。

## 地图上的碰撞轮廓

导航代价地图运行、定位可显示时，地图自动叠加两条实时轮廓：

- 绿色实线：局部碰撞轮廓，包含当前 `footprint_padding`。
- 橙色虚线：全局代价地图轮廓。当前 `hold_initial` 固定朝向策略使用外接圆，由 64 边形近似，包住加边距后的底盘在任意朝向下的形状。

数据直接来自机器人 Nav2 的 `/fairino_navigation/local_costmap/published_footprint` 和 `/fairino_navigation/global_costmap/published_footprint`，使用实际发布的形状、尺寸及位姿。局部轮廓按消息时间从 `odom` 转换到地图坐标，全局轮廓已经在地图坐标中；界面不重复添加安全边距或旋转。

轮廓选择跟随 `FollowPath.heading_mode`：`hold_initial` 使用外接圆，`path_tangent` 使用原来的保守方形包络。两者为 Smac2D 提供基本相同的有效碰撞半径；局部碰撞仍按实际矩形及预测旋转扫掠检查。

外接圆半径由底盘轮廓和 `geometry.footprint_padding` 自动计算，当前约 0.508 m。64 边形外切该圆，并留有浮点解析余量，使各边到中心的距离不小于所需半径，避免用圆内接多边形时缩小保护范围。全局不重复增加边距；局部矩形仍按原配置添加边距。

Smac2D 根据膨胀后的中心栅格代价判断通行。与此前方形配置相比，新的有效碰撞半径基本一致，轮廓显示更接近实际判断方式；这不会利用固定朝向放宽窄通道限制。轮廓线不能完整表示障碍物周围的膨胀代价区域。

定位无可显示位姿、数据超过 1 秒未更新、连接断开或新地图与帧版本不匹配时隐藏轮廓，避免将旧位置画成当前位置。导航未运行或尚未发布轮廓时也不显示，不使用电脑端配置猜测机器人当前形状。

显示功能在重新打开地图/整体控制面板后加载，观察脚本随面板的只读连接传输。全局轮廓从方形改为外接圆需要重新部署导航配置，并在之后启动导航时生效；面板收到机器人发布的新轮廓后自动画成圆形。显示功能本身不会启动服务或发送运动指令。

## 部署

部署入口仍是 `bash scripts/run.sh deploy navigation --execute`。它会在导航服务停止时，把插件源码编译到独立的新安装目录，运行无节点/无电机操作的 pluginlib 加载检查，成功后才更新导航运行文件。构建或加载失败不会替换现有服务配置。之后按现有流程启动导航；部署本身不启动服务或使能电机。

本次协调更新同时涉及机器人上的导航插件/门控和电脑端传输的底盘 Worker。完整部署导航后，需退出并重新打开电脑端面板，再按正常流程重新接入导航底盘；旧面板进程不会自动更新其已载入的 Worker。若在活动导航期间更换 Worker 会话，应结束并重新启动导航，不能让原目标自动续跑。部署及重连应在原导航结束、底盘确认下使能后进行。

机器人构建环境需 CMake、C++17 编译器、make，以及 Humble 的 Nav2、pluginlib、TF 和 `diagnostic_msgs` 开发/运行依赖。旧服务若仍安装 DWB 配置，不会因本地源码修改自动切换。完整安装流程见 [部署说明](deployment.md)。


## 保存位置点并作为导航目标

在控制页面的导航区输入点名称，点击“保存当前位置与朝向”。仅在已选用保存地图、定位就绪、机器人位姿有效且反馈新鲜时允许保存。记录为 map 坐标的 X、Y（米）和朝向（弧度，界面显示为度），不记录原始里程计坐标。

可以保存多个点。下拉列表显示名称、坐标和朝向；选择后点击“设为导航目标”，页面填入目标并在地图显示，随后可以预览路径或点击“开始导航”。选择和保存均不会发送运动指令。列表支持刷新、删除，同一机器人同一地图内不允许重名覆盖。

当前 hold_initial 策略下，保存点导航先保持开始时的车身朝向到达位置，待平移停止后再对齐保存朝向。两阶段属于同一个 NavigateToPose 目标；取消、保护停止会终止整个任务。到达位置不会提前报告任务完成，最终位置、朝向和停止速度均满足原目标检查器后才完成。两阶段均保留局部碰撞检查、故障保护和每 1 秒持续重规划。手输坐标同样填写终点朝向并按这两个阶段执行；path_tangent 配置仍沿路径调整朝向并使用保存的终点朝向。

位置点保存在控制电脑仓库的 .local/navigation/waypoints.json（149 服务器使用 /home/xense/fairino_slam/.local/navigation/waypoints.json）。按机器人地址、用户、地图文件路径、地图修改时间及坐标系区分，重新打开页面或重启同一地图的定位后仍可使用；切换或更新地图后不混用旧点。发送保存点目标前，机器人还会复核地图路径和版本。文件使用锁和原子替换，多个面板同时保存不会互相覆盖；损坏文件会报错并保留原文件。

此功能新增 navigate_to_saved_pose.xml 和行为树节点，需要完整更新导航部署并重新打开控制页面后使用；部署不会启动导航或使能机器人。
