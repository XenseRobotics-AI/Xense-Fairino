### 2.1 底盘

`W/S` 前进/后退，`A/D` 横移，`J/L` 左/右转。方向以机器人自身为准。程序启动时先使能转向轴并回正，再进入八轴控制。松开按键停止速度指令，空格/Esc 执行停止/退出流程；断流或故障会终止该次控制。它不是导航、路径规划或自主避障。

### 2.2 上半身关节与身体联动

已通过用户观察建立的关节对应：左臂 J1–J7；右臂 J8–J14；J15 头部；J16 腰部旋转；J17 整体侧倾；J18–J20 为折叠结构的三个关节。折叠轴配合决定上身高度和前后姿态。

单轴程序保留角度步进，新增绝对角度输入与可调计划速度；此前固定 ±3°活动范围已取消。计划速度和“用实测速度触发中止”是两件事，不能把速度输入框理解为所有保护阈值。

身体联动程序使用 360/380 mm 两段模型：低/中/高预设、前倾 0–45°、侧倾 ±15°、腰旋转 ±90°；侧倾仅在高度≥90%、前倾≤5°时开放。这些是该身体程序的应用范围，不是厂家确认的机械硬限位。速度默认 5°/s，可调。选择预设只更新输入，点击执行才运动。

`body_control/body_config.json` 已有 `upright_confirmed=true`，来源是用户于 2026-10-12 18:01:33 运行标定，将当时胸部姿态声明为竖直；三轴角度和约 −4.977568°。它不是 IMU 重力测量，也不代表各轴零偏和整机几何均已标定。模型升降毫米数及保持前后位置的效果仍需实测；现有身体程序文档记录的是离线验证和只读检查，不宣称所有联动动作都已完成真机验证。

### 2.3 TCP 键控与运动学

TCP 键控用连续按键控制平移与旋转，复用厂家七轴库 `libkine_FR_7Axis.so` 进行 FK/IK，并结合独立模型校验、双臂安装变换及腕心到法兰中心 `[-106, 0, 0] mm` 偏移。

统一胸部坐标：X 前、Y 左、Z 上。腰和折叠结构运动后，胸部轴可能不与地面平行；这不是基于底盘/地面的全身世界坐标解算。当前 TCP 为法兰中心；加转接件或灵巧手后，需要另外设置实际工具变换，不能直接把掌心当成已建模 TCP。

TCP 键控与 VR 是两个不同执行程序。TCP 键控仍使用自己的速度目标和分段轨迹机制，不能把它当作下面的 450 Hz TCP 插值遥操。

### 2.4 PICO 双臂遥操

当前链路：

```text
PICO 手柄跟踪与按键
  → Wi-Fi → 电脑上的 XRoboToolkit PC Service / SDK
  → 相对位姿映射、灵敏度、按键冻结
  → TCP 平移线性插值 + 四元数最短弧 SLERP
  → 每个采样点进行双臂 IK
  → 有线 SSH → 上半身 RK3588 的 ROS 控制器
  → 单点位置保持 → EtherCAT → 各关节驱动器
```

新包快捷入口 `bash run.sh vr` 等价于：

```bash
bash run.sh pico fairino --execute \
  --mode mirror_same_direction --rotation-mode mirror \
  --hand-mapping crossed --freeze-buttons --sensitivity 0.25 \
  --interpolation-hz 450 --receiver-hz 500 --interpolation-delay-ms 12
```

| 参数/频率 | 含义 |
|---|---|
| PICO 约 90 Hz | 曾测得的输入数据更新频率；不是每次启动都保证精确 90 Hz |
| 插值/IK/下发 450 Hz | 电脑希望每秒生成并发送 450 组目标；`--interpolation-hz` 与 `--command-hz` 同义 |
| 接收轮询 500 Hz | 机器人端轮询设置，不能等同实际有效接收/ROS 发布频率 |
| 回传默认 100 Hz | 机器人状态回电脑的设置，不是 PICO 采样频率或物理到位次数 |
| 缓冲 12 ms | 用已收到的前后两帧插值；缺少后一帧就保持最近目标，不外推 |

实际频率看运行日志。原始 `pico fairino` 不带频率参数时仍默认 90/200/100 Hz；`vr` 快捷入口才指定 450/500/100 Hz。程序要求下发≤接收≤500 Hz。

当前为 TCP 插值 v3：先在 TCP 空间插值，再做 IK。机器人端已移除旧的 30 ms 关节追赶段，接收位置目标后保持，直到下一个目标。它仍经过 ROS，不是直接从电脑发送 EtherCAT 帧。Home 另用同步的关节空间五次时间曲线，不应与遥操输入插值混淆。

| 手柄操作 | 行为 |
|---|---|
| 右手柄 / 左手柄 | 分别控制机器人左臂 / 右臂 |
| 握 Grip | 相对跟随该手柄；可同时控制两臂 |
| 松开 Grip | 该臂停止跟随并保持；重握重新建立起点 |
| 按住 A/X | 冻结旋转，只跟随位移 |
| 按住 B/Y | 冻结位移，只跟随旋转 |
| 同时按住两键 | 两个分量都冻结；松开不补走冻结期间动作 |
| 左摇杆上/下 | 调节灵敏度 0.25 / 0.5 / 1；松开 Grip 后重握 |
| 左摇杆按压、终端空格 | 暂停；Home 中则中止 |
| 右摇杆按压 | 回双臂 Home，再按中止 |
| Esc/Q/Ctrl+C | 结束并等待全部 20 轴下使能确认 |

默认使能后先回 Home，J15–J20 保持；`--no-auto-home` 可跳过本次自动回程。Home 角度在 `scripts/pico4/fairino/home_pose.json`，是工作姿态而不是机械零位。头显需要开启 Controller Tracking 和 Send，关闭用 A 键切换 Send 的选项，以免与冻结操作冲突。

遥操已取消此前起点半径以及活动手臂的应用层速度/加速度限幅；灵敏度不是速度上限。模型关节范围、厂家逆解检查、急停、故障、断流和非活动身体关节保持检查仍存在。不要将这描述成“所有检查全部取消”。

### 2.5 清错脚本：新版已经包含

**开机/重启后先检查故障。** 此前开机后使用控制程序时曾观察到全局 `0x0E10FF01` 与关节 `J15=30`，故障未清除会导致键控/遥操启动中止。`30` 为各轴 `errorcode` 的十进制值，按现有故障表属于驱动器 EtherCAT 通信类故障；具体受影响轴和故障原因仍应结合当次反馈、驱动器版本及日志判断。

等待服务和反馈稳定后，先运行 `bash run.sh errors`。若有故障，退出所有键控/遥操，确认机器人静止、全部未使能且急停已释放，再执行 `bash run.sh errors --execute`。脚本先上半身后底盘，每块板至多请求一次复位；清除后再运行 `bash run.sh errors`，确认全局及各轴错误码归零后再启动控制。无故障时无需清错；清除失败或立即复发时保留记录排查，不连续复位。完整启动步骤也见 [仓库 README](../README.md)。

历史依据：本机 `lerobot-xense/scripts/pico4/fairino/diagnostics/20261010-j15-reseterror-once.json` 记录了 `J15=30`、全局 `0x0E10FF01`，单次 `reseterror()` 后故障归零且仍未使能。该记录只说明当时的复位结果，不保证当前故障都能以同样方式清除。

新版文件：

- `scripts/pico4/fairino/clear_errors.py`：电脑入口、SSH、日志。
- `scripts/pico4/fairino/fault_reset_remote.py`：机器人端前置检查、单次复位、反馈复查。

```bash
bash run.sh errors                         # 只读检查上下身
bash run.sh errors --execute               # 先上半身后底盘
bash run.sh errors --part upper --execute  # 只处理上半身
bash run.sh errors --part base --execute   # 只处理底盘
```

实际调用厂家 Action 的 `reseterror()`，不是将 ROS 故障话题改成零，也不是直接修改驱动器错误寄存器。先检查反馈新鲜度、静止、未使能、急停和控制器占用；每块板至多发送一次。命令后继续观察 5 秒，最后至少 2 秒状态符合要求才确认成功。不会自动使能或开始运动。

程序被占用、仍有使能轴、急停未释放或故障条件不满足时，会拒绝执行。它不是任何错误都能强制清除的工具。最近保存的 10 月 13 日记录包含占用/仍使能导致的阻止执行，不能据此宣称机器人现在已经无故障。

**旧包是否有清错？有，但只有旧上半身版本。** `法奥机器人_20261009.zip` 和 `法奥机器人交接_20261009.zip` 中包含 `tools/reset_upper_once.py` 与 `upper_reset_remote.py`，旧命令为 `bash run.sh reset-upper --execute-reset`。新版保留兼容入口；日常以 `errors` 为准。转接件资料 ZIP 和厂家原始 RAR 不包含我们编写的清错工具。


`setup.sh base` 创建包内 `.venv/`；`setup.sh pico` 默认用系统 Python 创建 `.local/pico4/env/`，也可通过 `PICO_USE_CONDA=1` 使用已有 Conda。PICO 安装包/APK/ADB 放在 `vendor/assets/`，无需为这些已包含的文件重新下载。Python 包仍需安装，不能把它理解为完整离线系统镜像。首次安装不会替用户配置机器人端服务，也不会默认创建新的电脑开机自启服务。

先启动 `bash run.sh pico service`，头显选择电脑 IP、打开 Controller/Send，再运行 `bash run.sh pico monitor`。确认输入后启动遥操。若电脑已运行之前配置的 PICO 后台接收服务，无需再启动第二个相同服务。

链路测试入口：

```bash
bash run.sh pico latency --duration 25
bash run.sh pico fairino --link-check --duration 25
bash run.sh pico fairino --link-check --observe-ros --duration 25
```

第一条需要 PICO 的 USB 调试用于校时；后两条是模拟目标链路测试，不发真实运动目标。详细历史延迟、P95 含义及测量边界见 [有线方案与延迟说明](PICO遥操有线方案与延迟说明.md)。旧测量结果不能作为新电脑当前延迟的保证。
