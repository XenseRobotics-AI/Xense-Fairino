## 当前网络结构

```text
互联网
  │
房间路由器和无线接入点 KBE_OUT  192.168.31.1
  ├─ Wi-Fi ─ 笔记本 wlp0s20f3
  │           192.168.31.32/24   自动获取，用于上网
  │           192.168.58.205/24  手动附加，用于访问机器人
  └─ Wi-Fi ─ TP-LINK 192.168.58.11，Client 桥接
              └─ 机器人内部有线网络
                ├─ 192.168.58.1  上半身控制板
                └─ 192.168.58.3  底盘控制板
```

`/24` 表示子网掩码 `255.255.255.0`。电脑的 `.31.32` 是 DHCP 自动分配的地址，重新连接后可能变化；`.58.205` 是保存在 KBE_OUT 连接配置中的附加固定地址。

TP-LINK 的 Client 模式将机器人内部有线网络接入房间的无线网络。它不会把 `.58` 地址自动改成 `.31`，也不需要给两块控制板安装 Wi-Fi 网卡或驱动。

访问机器人时，电脑使用 `.58.205`，机器人可以直接回复同网段地址。访问互联网时，电脑通过 `.31.1` 默认网关上网。一个无线网络可以承载这两个 IP 网段；同一块网卡也可以有多个 IP 地址。

这套配置实现的是电脑无线访问机器人。机器人控制板自身访问互联网需要另外配置路由和网关，不会因为无线桥接就自动具备上网能力。

## TP-LINK 当前配置和重建步骤

| 项目 | 当前设置 |
| --- | --- |
| 工作模式 | **Client**，客户端桥接模式 |
| 管理地址获取方式 | 手动或静态 |

| 无线认证 | WPA-PSK/WPA2-PSK；密码 `<由设备持有人提供>` |
| BSSID 锁定 | 关闭，按 SSID 连接 |

| TP-LINK DHCP 服务器 | 关闭，自动启用也关闭 |
| 原有热点 `轮足_Robot_01` | 关闭 |

重建配置时，先通过网线和固定 `.58` 地址进入管理页。以下按照网页中的功能名称操作，不同固件的菜单文字可能略有差异。

1. 登录 `http://192.168.58.11/`，使用 `admin` / `<由设备持有人提供>`。
2. 在网络设置中，将工作模式改为 **Client**。本方案使用桥接，不使用 Client-Router 路由模式。
3. 模式切换完成后，重新检查 LAN 管理地址，设为手动 `192.168.58.11`，掩码 `255.255.255.0`。
4. 关闭该设备的 DHCP 服务器及自动启用 DHCP 的选项，并关闭原来的 `轮足_Robot_01` 热点。房间路由器仍负责给普通上网设备分配 `.31` 地址。
5. 保存并应用 LAN 配置，再读取一遍，确认管理地址为手动固定地址、DHCP 已关闭。
6. 在无线连接设置中选择 5 GHz，扫描并选择 `KBE_OUT`，输入密码 `<由设备持有人提供>`，连接并保存。
7. 确认无线状态显示已连接，管理地址仍为 `.58.11`，DHCP 和原热点仍关闭。

**模式切换后必须复查地址和 DHCP。** 本次实际配置时，设备在切换为 Client 后自动将管理地址方式恢复为动态，并重新启用了 DHCP。因此不能只看提交成功提示，需要在切换后单独设置和核对。

设备里还保留着原来的管理网关 `192.168.58.254`、DNS `192.168.1.254` 和 `192.168.1.1`。这些地址并未验证可用；它们不是本方案中电脑上网的配置，不要抄到电脑的 Wi-Fi 网关和 DNS 中。同网段的管理访问和桥接转发不依赖这些管理网关、DNS 值。

## Ubuntu 电脑的无线配置

当前电脑已经完成本节配置，日常只需要连接 KBE_OUT。以下用于恢复配置或配置其他 Ubuntu 电脑，命令适用于使用 NetworkManager 的系统。

先查看网卡和连接名称：

```bash
nmcli device status
nmcli connection show
```

当前无线网卡叫 `wlp0s20f3`，连接名称为 `KBE_OUT`。其他电脑需要替换成自己的名称。

如果还没有连接该 Wi-Fi，执行以下命令，并在提示时输入密码 `<由设备持有人提供>`：

```bash
nmcli --ask device wifi connect "KBE_OUT" ifname wlp0s20f3
```

保留自动获取上网地址，增加机器人网段地址：

```bash
nmcli connection modify "KBE_OUT" \
  ipv4.method auto \
  ipv4.never-default no \
  +ipv4.addresses "192.168.58.205/24"

nmcli device reapply wlp0s20f3
```

| 参数或命令 | 作用 |
| --- | --- |
| `ipv4.method auto` | 继续从房间路由器获取 `.31` 地址、网关和 DNS |
| `ipv4.never-default no` | 允许此 Wi-Fi 承担默认上网连接 |
| `+ipv4.addresses` | 在自动获取地址之外，再增加一个固定地址 |
| `nmcli connection modify` | 修改保存的连接配置，下次连接仍生效 |
| `nmcli device reapply` | 将已保存配置应用到当前网卡，通常无需断开重连 |

如果系统提示权限不足，可在相应的 `nmcli` 修改命令前加 `sudo`。如果 `reapply` 提示该修改不能直接应用，可执行 `nmcli connection up "KBE_OUT"` 重新连接；这会短暂中断该 Wi-Fi 上的连接。

不要将整个 Wi-Fi 的 IPv4 方法改成只有 `.58` 地址的手动模式，也不要给 `.58.205` 配置 `.58.11` 作为默认网关。本方案的默认上网网关来自房间路由器 `.31.1`。

**换电脑时不能照抄本机已使用的地址。** 截至 2026-10-12，本机无线口保存 `.58.205`，有线口保存 `.58.201`（当前网线已拔除）；`.58.202` 已确认与 `jimu-Legion-Y9000P-IRX8-39.local` 冲突。同网段内每台设备的 IP 必须唯一。新电脑应选择经确认未被占用的其他地址，再替换命令中的地址。只连接 KBE_OUT、没有增加 `.58` 地址的新电脑，通常不能直接访问机器人。

附加地址只保存在 `KBE_OUT` 这个连接配置中；切换到其他 Wi-Fi 不会自动复制过去。

## 验证连接和日常使用

查看地址和实际路由：

```bash
ip -4 addr show dev wlp0s20f3
ip -4 route
ip route get 192.168.58.3
```

拔掉网线后，应看到无线网卡同时有 `.31` 和 `.58` 地址，关键路由形如：

```text
default via 192.168.31.1 dev wlp0s20f3 ...
192.168.58.0/24 dev wlp0s20f3 ... src 192.168.58.205 ...
```

查询 `.58.3` 路由时，应该使用 `dev wlp0s20f3 src 192.168.58.205`。路由中的 metric 数字可能变化；判断重点是所用网卡、源地址和默认网关。

分别测试无线盒子和控制板：

```bash
ping -c 5 192.168.58.11
ping -c 5 192.168.58.1
ping -c 5 192.168.58.3
```

然后打开机器人控制网页，或执行上面的 SSH 命令。原控制程序继续使用 `.58.1`、`.58.3`，不需要因改为无线而改 IP。网络连通与电机使能是两个独立条件：网页能打开并不代表电机已经使能。

2026 年 10 月 6 日拔掉网线后的实测结果如下。每个设备测试 10 个 Ping 包，结果用于确认当时连通，不代表长期延迟保证。

| 设备 | 平均延迟 | 最大延迟 | 丢包 |
| --- | --- | --- | --- |
| `.58.1` 上半身控制板 | 5.3 ms | 9.1 ms | 0/10 |
| `.58.3` 底盘控制板 | 6.1 ms | 14.3 ms | 0/10 |
| `.58.11` TP-LINK | 16.3 ms | 112.1 ms | 0/10 |

两块控制板的 SSH 服务可连接，机器人控制页和 TP-LINK 管理页返回 HTTP 200，电脑访问互联网正常。网络测试未发送电机使能或运动命令。

## 有线备用连接

本节保留 10 月 6 日的备用方案，使用后电脑有线口只配置 `.58` 地址。本机现在已有保存的有线 `.58.201` 配置，不必执行本节旧命令。若切回有线并通过有线口接收 PICO，应保留有线口的 DHCP `.31` 地址，按 [有线说明](PICO遥操有线方案与延迟说明.md) 核对。

10 月 6 日关闭 TP-LINK DHCP 后，笔记本原来的 `Wired connection 1` 仅自动获取 IPv4 地址；当时的 `.58.101` 未作为固定地址保存。后来已补上固定地址配置，目前有线口保存的是 `.58.201`。

下面的命令用于**需要有线备用连接时**执行，文档整理过程中没有执行它们。先确认 `.58.101` 没有被其他设备使用，再将笔记本接到机器人的内部网络接口。

```bash
nmcli connection modify "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses "192.168.58.101/24" \
  ipv4.gateway "" \
  ipv4.dns "" \
  ipv4.never-default yes

nmcli connection up "Wired connection 1"
```

这样，有线连接用于访问 `.58` 机器人网络，不会接管默认上网路由；Wi-Fi 继续上网。有线和无线同时具有 `.58` 地址时，通常有线的 metric 更低而优先使用，但应以 `ip route get 192.168.58.3` 的结果为准。

配置好有线地址后，即使机器人还没有连上房间 Wi-Fi，也可以通过网线访问 `.58.11` 修复无线连接。这里的有线口指机器人内部普通以太网接口，不要连接控制板与电机之间的 EtherCAT 总线接口。

## 常见问题和恢复方法

| 现象 | 检查和处理 |
| --- | --- |
| Wi-Fi 能上网，机器人 IP 不通 | 查看无线网卡是否有 `.58.205/24`，以及到 `.58.3` 的路由源地址是否为 `.58.205` |
| `.58.11` 不通 | 确认电脑连接 KBE_OUT；检查附加地址；必要时用有线固定地址进入管理页，确认 TP-LINK 无线连接状态 |
| `.58.11` 通，但 `.58.1` 或 `.58.3` 不通 | 检查对应控制板是否供电、内部网线和 IP 是否正常 |
| 换一台电脑后不通 | 新电脑也需要自己的、未占用的 `.58` 地址；房间 Wi-Fi 的客户端隔离功能也可能阻止设备互访 |
| 插网线后上不了网 | 检查有线连接是否错误提供了默认网关；机器人专用有线连接应设 `ipv4.never-default yes` |
| 插回网线仍访问不了机器人 | 检查是否启用了已保存 `.58.201/24` 的 `Wired connection 1`，按新有线说明核对配置和 `ip route get` |
| 网页能开，但控制没有动作 | 再检查急停、使能、控制服务和机器人反馈，不能仅凭此现象判断为 Wi-Fi 故障 |
| 换房间 Wi-Fi 后失联 | 需要修改 TP-LINK 上游 SSID/密码，同时给电脑的新 Wi-Fi 连接配置增加 `.58` 地址；上游不能与机器人产生地址冲突 |

如需移除本机 KBE_OUT 连接中的机器人附加地址，执行：

```bash
nmcli connection modify "KBE_OUT" \
  -ipv4.addresses "192.168.58.205/24"
nmcli device reapply wlp0s20f3
```

这会保留自动获取的上网地址，但本机将不能再按当前无线方案直接访问 `.58` 机器人网络。要恢复访问，重新增加该附加地址即可。
