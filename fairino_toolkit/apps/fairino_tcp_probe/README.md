**当前已对齐统一胸部坐标：X 前、Y 左、Z 上，左右臂的按键含义相同。**
原点沿用厂家整机 URDF 的 `body_Link`；胸部 XYZ 对应原 body 的 −Y、+X、+Z。
坐标随胸部运动和倾斜，不是固定地面坐标；键控轴也不随手腕自身旋转。
窗口位置、RPY 和检查输出的 `pose_mm_deg` 均为胸部坐标；检查输出额外保留
`base_pose_mm_deg` 以供核对厂家基座位姿。切换坐标后显示数值会改变，启动保持
当前姿态，不会因为坐标定义改变而回零。

安装关系来自新增 `轮足机器人URDF模型外发-v1.0-20260731.zip`。`tcp_frames.py`
保存两侧固定关节原始 xyz/rpy，并计入 CAD 基座到厂家 DH 原点的小偏置；
安装参数与 PICO 的 `art7-both-chest-urdf-20260731-v1` 映射通过一致性测试。
两个 DH 基座原点在胸部约为 `[0,+62.5,329]` / `[0,-62.5,329] mm`。
这些是厂家名义参数，尚未实物标定；不采用整机模型中尚有疑问的头腰编号、
关节限位或动力学数据。

**TCP 仍为法兰安装面中心**，使用相对腕心的固定偏移 `[-106, 0, 0] mm`，不含
夹爪长度。显示和目标在胸部表达，逆解前转换到对应臂基座，厂家 FK/IK 仍沿用
原 ART7-R7 模型及末端轴约定。仅增加安装坐标转换，没有再次叠加法兰偏移。

速度设置：

| 参数 | 默认 | 可调范围 |
|---|---|---|
| 关节速度上限 | 2°/s（原 0.5°/s 的四倍） | 0.1–4°/s（原上限 1°/s 的四倍） |
| TCP 平移请求速度 | 8 mm/s | 0.1–8 mm/s |
| TCP 旋转请求速度 | 2°/s | 0.1–2°/s |

平移/旋转上限分别由原规划中的 2 mm/s、0.5°/s 放宽四倍。关节速度上限优先，接近不利姿态时 TCP 实际速度会降低。这里只调整本程序的软件速度约束，没有修改驱动器的厂家速度、过载或硬限位参数。活动手臂的异常实测速度阈值由 2°/s 放宽到 8°/s；另一臂和躯干的保持速度阈值仍是 0.5°/s。原独立关节点动程序默认保护不变。

旋转命令是在法兰中心绕胸部 X/Y/Z 轴旋转，正方向遵循右手定则。显示姿态为
相对胸部的 RPY，矩阵约定 `Rz(yaw) Ry(pitch) Rx(roll)`。绕某轴旋转不一定
只改变对应的一项显示欧拉角。

## 控制和停止方式

本版模型标识为 `ART7-R7-20260615-flange-x-106mm-v2`，旧的零偏移请求无法通过新版本校验。正解先把腕心转换为法兰中心；逆解先把法兰目标转换回腕心再调用厂家库，固定偏移只计算一次。每次长按旋转记录当时法兰中心，并以 2/s 的位置反馈增益逐渐消除连续近似漂移；保持点不能在长按期间更改，偏差超过 0.5 mm 停止。松键后清除保持点，下次按键从新位置开始。

当前连续控制协议为 `tcp_hold_chest_v2`，请求同时携带安装坐标版本。
电脑和机器人端均按胸部轴重建目标；旧基座方向请求、缺少/错误的坐标版本、
把基座方向目标伪装为胸部目标的请求都会被拒绝。旋转保持点仍在该臂基座中
保存，使已有保持反馈和制动逻辑可继续使用。PICO 的远端源代码包也已包含
新增纯 Python 坐标模块，保持共享导入兼容。

笔记本约每 0.1 秒使用厂家纯数学库 `libkine_FR_7Axis.so` 解算小范围 TCP 目标，由与参考角度之差得到局部关节速度。上半身 `192.168.58.1` 上的 ROS 节点独立验证正解、参数范围和指令时效，按关节上限缩放速度，再以目标 50 Hz 发布包含全部二十轴位置和速度的短轨迹到 `/fairino_upper_identify/joint_trajectory`。既有 `ros2_control` 控制器经 EtherCAT 驱动关节；未启动厂家 SDK 运动服务。50 Hz 是程序设定的发送目标，不是已验证的实机最高 TCP 控制频率。

轨迹采用 80 ms 速度过渡和 200 ms 零速结束段，持续更新时速度连续，避免每一步完成后停住。松键后单独发送减速轨迹，最大计划减速时间约 0.2 秒，另有键盘、通信和控制响应延迟；不能把它理解为物理瞬间停止。每条轨迹都有有限长度和零速终点，即使后续发布中断也不会无限继续。

这一版通过连续局部逆解跟随所需 TCP 方向，再做关节空间插值；不是严格笛卡尔直线插补，未承诺绝对轨迹精度、姿态不漂移或碰撞规避。

连续逆解请求超过 0.25 秒未更新，即使 SSH 心跳仍在也停止；硬件反馈超过 0.4 秒、通信往返超过 0.45 秒等故障沿用全轴下使能。反馈同时检查实际/指令位置差（0.004 rad）、控制器指令与本程序预测轨迹差（0.006 rad）、非活动十三轴保持偏差（0.3°）、实际速度及硬件故障。因本版使用 topic 接口，跟踪误差由本程序显式监控，不依赖 Action 返回成功。参考 [ROS 2 JTC 接口说明](https://control.ros.org/humble/doc/ros2_controllers/joint_trajectory_controller/doc/userdoc.html) 和 [轨迹插值说明](https://control.ros.org/humble/doc/ros2_controllers/joint_trajectory_controller/doc/trajectory.html)。

接近模型限位、逆解跳变或解算失败时停止并保持，必须松键后换方向/调整速度。模型范围约 ±175、±110、±175、−75~110、±175、±70、±85°，来源为本地 `RD53-ART7-R7-双臂URDF和模型-v1.0-20260615`，不是从驱动器读取的物理硬限位。DH 来源为厂家 [ART7-R7 DH 参数](https://fairino-art-doc.readthedocs.io/zh-cn/latest/ART7Manual/art_product.html#dh)：d 为 187/0/290/0/310/0/0 mm，第六轴偏置 +90°。没有加载单机 DH 补偿、工具标定或碰撞模型。
