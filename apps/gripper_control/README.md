# TacCap / XTac 夹爪调试

运行 `bash run.sh console` →「夹爪调试」，或单独运行 `bash run.sh gripper`。
界面和机器人端控制实现共用，电脑负责显示，上半身通过已经安装的
`/home/fairino/umi/.venv/bin/python` 调用 main 分支引入的官方 TacCap SDK。
SDK 安装、设备供电/USB 与原始测试记录见 [umi 说明](../../umi/README.md)。

1. 填上半身 IP、用户和 SSH 密码，点击「扫描 / 连接（只读）」。
2. 默认按 SDK 的 Left/Right 和 Follower 身份分配，显示固件 SN 与串口。
   可在连接前用固件 SN 明确指定左右；未知身份、重复身份不猜测，缺少的一侧保持灰色。
3. 设置电机力矩和速度，点击对应夹爪「使能 · 保持当前位置」。
4. 滑条只修改目标；点击「执行目标开度」「张开」或「闭合」才运动。
   0% 闭合、100% 张开，中间为连续开度。
5. 「暂停 / 保持」取消当前行程、保持位置；「下使能」或断开结束控制。

默认夹持力矩 **1.1 Nm**、电机轴速度 **0.25 rad/s**。力矩不是指尖力 N；
每次使能前按实际电机规格和固件生效包络校验，使用官方 `ForcePositionController`，
先启动状态流并以当前位置播种，再使能。运动中只读取控制器 snapshot，
不额外轮询串口。没有自动清错、标定或固件配置写入。

夹爪与上半身关节分别持有控制权；夹爪调试和 PICO 夹爪控制互斥。
远端另有进程锁与 SDK 串口独占。输入/反馈确认中断退出时请求下使能；
PICO 连续目标中断 0.25 秒先保持，随后连接超时退出。

连接后会显示使能前诊断，包括固件版本、故障有效标记、当前/历史故障及包络不匹配。
显示开度、温度说明已经连接，不代表使能检查通过。诊断使用缓存的只读结果，
控制器运行期间不额外轮询串口；点击使能仍会重新读取并复查，不自动清错或改包络。

历史 `0x00000004`（SDK 故障表：欠压），诊断 flags 为 `0x15`，缺少固件 FwValid；

缺少有效标记的固件故障字段不能当成已确认无故障。该次检查没有清错、运动或写入固件配置。
