PICO + ART7 C++ 联合限位 IK 独立实机测试
=====================================

这是单独的终端程序。2026-10-26 用户反馈当前直接 IK 实测良好后，主控制台也已接入
同一个 C++ 求解器和连续旋转输入；主入口见 scripts/pico4/README.md，默认选择「联合限位 IK」。
本独立程序保留，下面描述的是它自己的机器人端求解与发布流程。
PC 端沿用 PICO 输入、Grip 基准和 TCP 插值；机器人端用 C++ 联合限位 IK
直接求完整 TCP 目标，以最后一次已发布关节位置为种子，沿用原单点位置发布接口。
双臂一起校验、一次发布，再一起提交参考。厂家 IK 仅用于启动正逆解检查。
部分可行解的残余误差始终对完整目标计算，不标记为已经完全到达。

按用户要求，当前入口已取消额外的逐周期关节速度、加速度约束，以及0.5秒响应
跟踪层、全七轴命令制动距离限制和与旧10°/s限速绑定的20°/s实测速退出门槛。
--speed-deg-s / --acceleration-deg-s2 / --braking-deg-s2 参数已删除；传入会报错。
松开输入时保持最后一次已发布位置，并另行确认实机停稳，与原位置控制链路一致。
原联合腕部范围、2°静态余量和实测速预测检查仍保留。
当前离线验证见 logs/20261026-native-pico-direct-ik/REPORT.txt；用户已反馈修订后实测良好。
主控制台接入另见 logs/20261026-native-pico-main-integration/，本次接入未启动实机运动。
较早的118mm/70°回放和0.5秒Servo对照属于历史实现，不代表当前直接IK版本。

启动（在项目根目录）
--------------------
1. 先退出原上半身遥操/控制台控制会话，确认机器人处于合适的静止起始姿态。
   本程序沿用原控制器所有权锁，拒绝抢占仍在运行的运动控制器。
   不自动回 Home；不提供夹爪、身体升降、底盘运动功能。

2. 如 PC Service 尚未启动，在一个终端运行：
   bash scripts/pico4/run.sh service
   头显连接电脑，开启 Head / Controller Tracking / Send，关闭 A 键切换 Send。

3. 另一个终端先运行只读检查：
   bash scripts/pico4/native_ik_test/run.sh --check
   默认机器人地址 192.168.58.1、SSH 用户 fairino，可用 --host / --user 修改。
   检查包含机器人端编译/加载 C++、读取硬件和模型/初态检查；不使能。
   机器人端需要 ROS Humble 的现有环境、python3 + numpy、g++（支持 C++17）。
   程序将本次源码传到机器人临时目录，编译结果缓存于 /tmp/art7-ik-native-cache。
   缺依赖时会在使能前失败，不自动安装系统包或修改机器人配置。
   --execute 使能前额外连续观察 1 秒硬件反馈；年龄超预算或新硬件帧不足时
   拒绝使能。100 Hz 状态回传不等于 100 Hz 新硬件反馈。

4. 建议先单臂、低灵敏度测试，再测双臂：
   bash scripts/pico4/native_ik_test/run.sh --execute --arm left
   bash scripts/pico4/native_ik_test/run.sh --execute --arm right
   bash scripts/pico4/native_ik_test/run.sh --execute --arm both

   --execute 会使能全部 J1–J20；未选择的手臂与 J15–J20 保持。
   默认同向映射 first_person、同侧手柄、100 Hz、灵敏度 0.25。
   当前入口不再额外裁剪关节指令速度和加速度。
   面对面需要显式选择 --mode mirror_same_direction 或 --mode mirror；
   auto 手柄映射在面对面模式交换左右，与原输入映射一致。
   固定指尖 TCP 使用 --tcp-tool taccap（要求现有工具安装配置已确认）。
   默认 --tcp-tool flange，现场必须选择与测试目标一致的 TCP。

操作
----
握住对应 Grip 跟随，松开对应 Grip 后该臂保持最后发布位置；另一臂可继续。
空格：双臂保持暂停；松开两侧 Grip 并停稳后重新握下恢复。
c：机器人停稳、两侧 Grip 松开、右摇杆回中后，使用头显校准正前方。
q / Esc / Ctrl+C：先保持最后指令并确认停稳，再退出并下使能，检查终端确认消息。
--freeze-buttons：按住 A/X 冻结旋转，按住 B/Y 冻结平移，松开不补走。
不使用原控制台的 Home、夹爪、升降或底盘快捷键。
腕部联合限位始终开启，本入口没有关闭保护的选项。
独立入口对选中手臂使用连续的锚定旋转映射，跨180°不会因0.25灵敏度跳变90°。
为避开360°处的旋转轴不确定性，单次Grip原始手柄连续旋转超过270°时暂停，
要求松开双侧Grip后重握；这是手柄原始角度范围，不是机器人关节限位。
共享正式PICO入口的映射代码未修改。

保护与停止含义
--------------
静态各关节范围、腕部二维联合范围与静态 2° 余量在 IK 内部约束。
原 WristGuard 按实测腕部速度预留0.2秒预测余量，并保留原合法向内退回规则。
每个新运动目标发布前，以原独立 FK、原 WristGuard 复查实测→目标和前次命令→目标。
两臂任一失败均不提交该双臂提案；可恢复时保持最后指令并要求重新松握。
无目标的保持命令必须严格等于最后发布位置，不重新求IK，不把旧目标的剩余误差继续发出。
如原 stop_stream，保持时不因新出现的动态速度余量拒绝重发同一位置；静态边界、
独立FK、等值检查以及硬件故障保护仍执行。

输入租约默认 150 ms；PICO 采样年龄包含在目标租约中，旧采样不会因重复发送续命。
客户端在读取 PICO 帧后、接收端在锁内取得输入快照后取当前时间，避免将
本周期内刚到达的新帧误判为负年龄。150 ms 门槛保持不变，真实过期仍触发暂停。
PICO 输入丢失但 SSH/硬件正常时，保持最后指令并维持使能，等待停稳、松握恢复。
PC 退出、SSH 中断等退出路径完成本地停止后清理下使能。
硬件故障、急停、使能丢失、反馈过期或无法确认保持等异常走下使能清理。
机器人端默认限制收到硬件反馈后的年龄不超过 60 ms，并监测控制器指令回报。
沿用原VR运动臂速度策略，未移动身体关节的1°/s异常监测仍保留。
停稳需新的硬件反馈确认指令目标和实测速度≤0.005 rad/s；
这些条件必须在连续新硬件反馈中保持至少 100 ms，才切回静止保持状态。
command_stopped 只代表关节位置指令不再改变，不代表机械臂已经停稳。

本程序不是硬实时控制器，也不再基于30°/s²假设声称具有确定制动距离。
60 ms 是反馈年龄预算，不能证明硬件内部隐藏延迟或时钟准确度。
联合腕部限位不是自碰撞、环境避障或完整动力学安全证明。
这是独立实测入口；离线回放通过不等于已经完成真实机器人验证。

日志与离线验证
--------------
会话日志：.local/pico4/native-ik-test-logs/YYYYMMDD-HHMMSS.jsonl
目标日志：同名 .actions.jsonl，包含完整 TCP 目标与启动参数。
退出日志：同目录 *.exit.jsonl，单独保留首个退出原因及最终下使能状态。
远端记录源码包 SHA-256、IK 误差/耗时、停止原因、反馈与下使能确认。
native_test.input_timing 和停止事件记录带正负号的心跳、往返与目标年龄；
客户端 input_pause 记录采样年龄和 Grip 状态，可区分输入过期与等待重新松握。
终端“已使能就绪”表示接收端就绪；输入异常后仍需松开双侧 Grip、停稳后再握。

仅运行离线单元测试（不会连接机器人）：
  PYTHONPATH=src:. .local/pico4/env/bin/python -m unittest discover \
    -s scripts/pico4/native_ik_test -p 'test_*.py' -v

历史保护审计及旧实现回放见 logs/20261026-native-pico-history/，包含源日志路径与源码哈希。
tools/replay_native_pico_history.py明确使用归档的旧限速规划器，只用于历史对照；
当前直接IK回放使用 logs/20261026-native-pico-direct-ik/ 中的验证脚本。
