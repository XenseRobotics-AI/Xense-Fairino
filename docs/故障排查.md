# 开机检查与故障排查

在仓库根目录执行。开机/重启后可能出现全局 `0x0E10FF01`、各轴错误码 `30`，如 `J15=30`。现有故障表归为驱动器 EtherCAT 通信类故障，具体原因按当次反馈与日志判断。

项目内 [真实历史样例](../data/diagnostics/startup-fault30-reset.json) 记录了单次复位后故障归零且仍未使能。EtherCAT 从站达到 OP 通信状态与错误寄存器归零是不同状态。

```bash
bash run.sh errors
# 有故障时：退出控制程序，确认静止、全部未使能、急停释放
bash run.sh errors --execute
bash run.sh errors
```

默认先上半身后底盘，每块板至多请求一次 `reseterror()`，随后观察 5 秒，末尾至少 2 秒故障为零、静止且未使能才确认成功。清错不使能、不回 Home、不发运动目标。

```bash
bash run.sh errors --part upper --execute
bash run.sh errors --part base --execute
```

| 问题 | 处理 |
|---|---|
| 控制锁或运动控制器占用 | 正常退出相应控制程序，再只读检查 |
| 仍使能或运动 | 核对下使能结果和实时反馈 |
| 急停/上下板转发异常 | 检查按钮、上半身状态及转发 |
| 反馈超时 | 检查网络、服务和反馈链路 |
| 命令成功但故障未归零 | 以复查反馈为准 |
| 复发或 FATAL 故障 | 保存日志排查底层原因，不循环复位 |
| SSH 超时或清错中断 | 先只读检查，不自动重试 |

记录写入 `scripts/pico4/fairino/diagnostics/*-fault-reset/`。代码：[清错入口](../scripts/pico4/fairino/clear_errors.py)、[机器人后端](../scripts/pico4/fairino/fault_reset_remote.py)。
