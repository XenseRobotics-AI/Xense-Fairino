# SLAM 合并与 PICO 模型演示

`slam` 原本是独立项目，现保留 Git 历史合入 `modules/fairino_slam/`。控制台继续使用原地图布局、图层和整机页面，地图数据与导航执行改用该模块。旧 `tools/build_navigation.py`、地图/导航命令及安装入口均转发同一模块，避免生成配置与实际启动使用不同实现。

## PICO 控制模型

```bash
bash run.sh teleop --demo
```

也可正常打开 `bash run.sh console`，进入 PICO 页，将「运行目标」改为「控制台模型（Demo）」。`--demo` 会将整个控制台置于离线演示，地图使用样例数据。

1. 点击「启动 PICO 接收服务」，在头显选择电脑 IP，开启 Head / Controller / Send。
2. 选择面对面或第一人称、IK 解算器（联合限位 IK / 原厂 IK / TRON2 QP IK）、起始 Home、TCP；按需勾选模拟夹爪和身体升降。
3. 点击「启动模型 Demo」，松开两侧 Grip 后重新握住对应手柄移动。
4. 松开 Grip 保持；暂停、回 Home、冻结位移/旋转和灵敏度操作沿用现有手柄约定。输入中断时停止更新并保持模型；恢复后先松开 Grip 再继续。
5. 点击「停止模型 Demo」结束。运行期间不能切换真机/模型或 IK；退出完成后才能切换。

默认面对面：右手柄控制左臂、左手柄控制右臂；第一人称为同侧。默认灵敏度 0.25，即 10 cm 手柄位移对应 2.5 cm TCP 相对位移。演示从所选 Home 和已标定身体高位初始化，采用理想关节跟随，不模拟电机延迟、惯性、负载和接触力。身体和夹爪只改变模型；底盘移动暂未加入此演示。

Demo 不需要 SSH 凭据，也不会启动上半身或夹爪的机器人连接。PICO 接收服务仍需电脑与头显通信。模型的数据来源在界面明确标注为演示；只读真机反馈不会覆盖它。

Demo 允许使用几何有效但尚未勾选实机安装确认的工具配置，以便预览安装角度；真机仍要求确认配置。切换到新版本界面需先结束当前 Demo，再关闭并重新打开控制台。

## 联合限位的视觉演示

双臂默认浅绿色。Demo 的 IK 选择和联合限位开关是两个独立选项：

| IK 选择 | 联合限位开启 | 联合限位关闭 |
|---|---|---|
| 联合限位 IK | 新数值 IK，腕部组合约束纳入求解 | Demo 专用数值 IK，仅保留单关节范围 |
| 原厂 IK | 原厂库求解，随后检查腕部及路径；必要时缩小 TCP 目标 | 仍由原厂库求解，仅保留单关节范围和正解校验 |
| TRON2 QP IK（Demo） | C++ Pinocchio + eiquadprog，单轴限位在 QP 内；腕部及路径在求解后检查，必要时缩小 TCP 目标重新求解 | 仍使用 TRON2 C++ QP，保留单关节范围和独立正解校验 |

原厂分支复用实机客户端的臂角参考和路径检查逻辑，但仅加载本机纯运动学库，不建立机器人连接。三种 Demo 均默认以 100 Hz 调度，并使用相同的手柄映射与连续旋转输入；实际计算频率受目标难度和电脑性能影响。切换算法需先停止；联合限位可在运行中切换，切换后暂停并要求松开 Grip 再重握。界面状态显示实际使用的算法，关闭保护不会把原厂或 TRON2 IK 替换成新数值 IK。

原厂 IK 开启保护后，缩小目标时会舍弃越界的手柄位移；无法求解时保持当前模型并提示原因，不会自动切换算法。如果某一臂求解失败，两臂都保持上一姿态。关闭保护允许模型进入腕部组合限位定义的干涉区。

程序根据**解算后实际显示的关节角**检查左腕 J6/J7、右腕 J13/J14；越过腕部几何包络时，对应腕心网格变红，返回可行范围后恢复浅绿色。红色使用现有包络的零余量边界；正常保护还包含配置的预留余量，因此接近保护边界不一定立即标红。

此提示是腕部联合限位模型所预测的干涉，不是 STL 全网格碰撞检测；不检测手臂互撞、手臂与身体/环境碰撞，也不产生接触阻挡。真机联合限位 IK 和 TRON2 IK 均要求保护开启，Demo 的关闭选项不会传入这两个真机后端。

## TRON2 QP 后端

来源为用户提供的 `tron2-ik-main.zip`，MIT 许可及原核心保留于 `third_party/tron2_ik/`。实际求解使用原 C++ Pinocchio / eiquadprog 实现。程序根据当前 ART7 的 DH 参数、各轴范围和所选 TCP 生成轻量 URDF；原 TRON2 尺寸、网格及立柱避障模型不适用于当前机器人，因此没有用于本 Demo。

在新电脑首次选择此后端前，从仓库根目录安装及编译可选依赖：

```bash
.local/pico4/env/bin/python tools/ik_experiments/setup_tron2_ik.py --install
bash run.sh teleop --demo
```

安装产物放在忽略目录 `.local/tron2-ik/`，原 PICO 环境的依赖不替换。已有依赖时可不带 `--install` 重新编译。缺少依赖或加载失败时明确报错并停止，不自动回退至其他 IK；实机入口在连接 PICO 或机器人前加载并检查模型正解。

在「运行目标 → 控制台模型（Demo）」中选择「TRON2 QP IK（Demo）」；在「运行目标 → 真机」中选择「TRON2 QP IK」。映射、灵敏度、TCP、冻结、Home、身体、夹爪和底盘沿用相应运行目标的共同控制链路。运行中不能更换 IK；默认仍为原有联合限位 IK。实机选择 TRON2 时强制开启腕部保护，客户端和接收端都检查，Demo 请求标记仍被实机接收端拒绝。

实机启动：

```bash
bash run.sh teleop
# PICO 页：运行目标「真机」→ IK「TRON2 QP IK」→ 启动遥操
# 或沿用命令行入口：
bash run.sh vr --ik-backend tron2
```

真机默认镜像面对面、灵敏度 0.25、TCP 插值 12 ms；联合限位 IK 和 TRON2 的 PC 目标采样/解算/下发均设为 **500 Hz**，机器人接收轮询也为 **500 Hz**。原厂 IK 保持 450/500 Hz。插值沿用原厂链路的 `CartesianBuffer`：TCP 位置线性插值、姿态 SLERP，然后解 IK，关节解直接发布；不增加接收端关节插值、逐周期关节速度/加速度限幅或追赶轨迹。500 Hz 是调度设定，实际频率受求解耗时、系统调度与通信影响；界面继续显示实测下发/接收频率，过期周期跳过，不补发历史积压。

沿用双臂 Home 默认行为。求解发生在电脑端，机器人端使用现有接收程序和独立正解/路径检查，无需安装 Pinocchio。规划结果同时检查前一规划参考与实测位置到目标的路径，并保留实测腕速的 0.20 秒预测余量；接收端以真实最后发布目标再次复查。规划拒绝时暂停并保持，松开 Grip 后可重新尝试，故障及退出仍按原控制链路处理。Demo 保持独立的默认 100 Hz 模型更新。

TRON2 的腕部联合约束**没有进入原 QP 内部**。外层检查参考关节到结果的整段路径；必要时缩小 TCP 目标重新求解，并舍弃越界手柄位移。它仍可能在边界停住，不能视为现有联合限位 IK 的等价替代。只有 Demo 可关闭保护观察算法本身，模型可进入红腕区域。不可达目标可返回未完全收敛的结果，界面显示部分解；独立正解及完整目标误差检查拒绝错误或使误差变大的结果。

七轴冗余允许同一个 TCP 对应多组关节角。关闭保护后手柄返回原 TCP，不保证恢复原关节组合或 2° 余量；若仍提示不能开启保护，先回 Home。现有数值 IK 的误差权重换算为米/弧度后约为 `位置误差² + 0.04×姿态误差²`，本 TRON2 接入沿用原包等权重 `位置误差² + 姿态误差²`，因此困难目标下的取舍也会不同。

TRON2 接入验证（2026-11-09）：PICO 回归 365 项、工作台回归 99 项、模型/核心 7 项全部通过，零跳过；含 54 组手柄平移映射、两侧工具旋转、腕部边界与静止保持、Home、断流及实机入口拒绝。200 组随机双侧 FK 与独立 DH 一致。600 组 Home 附近的双臂可达目标全部收敛，位置误差 <0.02 mm、角度误差 <0.006°；核心适配层中位耗时约 1.43–1.50 ms，95 分位约 1.59–1.65 ms。该耗时不含 PICO、界面或外层腕部重试，不代表全工作空间或实机性能。测试全部禁止 IP 网络连接，实际 GTK 选项显示已检查。记录在 `logs/20261109-tron2-demo/`。

实机入口与 500 Hz 更新后的最终离线回归：PICO 401 项、工作台 103 项、TCP 56 项、两套 IK 核心 30 项，共 **590 项通过，零跳过**。包括真实 TRON2 解通过模拟接收端发布、强制保护、实测速余量、双臂整体拒绝、断流、Grip、Home、冻结及 2 ms 周期的 TCP 位置/姿态插值检查。没有连接头显或机器人，也未使能。

为满足 2 ms 计算预算，独立 Python FK 改为等价稀疏 DH 乘法，TRON2 的重复动态库查找移至初始化；工具、目标、选项、关节、独立正解及路径校验均保留。新旧 FK 通过 1000 随机姿态、128 限位角点及双侧非对称 TCP 对照；TRON2 优化封装与原接口的关节解在 1e-14 rad 容差内一致。

90 Hz 合成输入经 12 ms 缓冲、500 Hz TCP 采样、真实双臂 IK、独立请求校验和 JSON 编码：两后端各 500 帧全部收敛，联合限位 IK 中位/P95/最大为 **1.27/1.37/1.96 ms**，TRON2 为 **1.04/1.12/1.34 ms**。该样例均未超过 2 ms，但不包括 SDK、网络、磁盘日志、真实反馈延迟和系统调度，也不证明所有目标均能稳定 500 Hz；实际运行仍以界面频率为准。最终测试、截图和可复现基准在 `logs/20261109-tron2-real/summary.json`、`pipeline-wrapper-optimized.json` 及同目录脚本。

## SLAM 与导航

配置位于 `modules/fairino_slam/config/`。导航使用直线优先、Smac2D 绕行、全向预瞄控制器；默认 0.10 m/s、0.20 rad/s，预瞄距离 0.20 m，控制器 3 Hz，速度门控 20 Hz、底盘执行约 50 Hz。后两层保持最近有效命令并检查时效，不做轨迹插值。默认行进保持起始朝向，到点后处理目标朝向；保存位置点绑定地图身份。

本次兼容修复允许 Smac 中间点携带全零四元数，随后根据路径重建朝向；起终点仍检查有效朝向。中文地图名和保存前验证、只读锁文件及服务阶段错误提示继续保留。

```bash
bash run.sh slam check                 # 离线配置与部署载荷检查
bash run.sh slam build-config --check  # 离线检查实际导航参数
bash run.sh slam help                  # 全部模块命令
bash run.sh test                       # 主工程与内置 SLAM 离线回归
```

本地合并不等于机器人端已经更新。新 ROS 插件需在机器人端按 [SLAM 部署说明](../modules/fairino_slam/docs/deployment.md) 部署后才会被运行中的 Nav2 使用。本次实现和验证不会自动部署、启动机器人服务或使能。控制台操作流程见 [导航页面说明](../apps/navigation/README.md)。
