# 法奥机器人功能汇总

本项目包含现有机器人控制功能的代码、运行模型、必要 SDK、安装入口和离线验证。本文所有路径均相对于仓库根目录，所有命令均在仓库根目录执行。

## 1. 项目结构

```text
fairino-robot-toolkit/
├── run.sh                         # 全部功能统一入口
├── setup.sh                       # 全部依赖安装入口
├── requirements/                  # 基础、PICO、诊断依赖
├── apps/
│   ├── fairino_keyboard/          # 底盘 WASD/JL
│   ├── fairino_upper_probe/       # J1–J20 单轴及共享通信
│   │   └── body_control/          # 身体升降与姿态联动
│   ├── fairino_tcp_probe/         # 双臂 TCP 键控与运动学
│   ├── lidar_viewer/              # 双雷达实时显示
│   ├── map_viewer/                # 按需建图、固定底图、AMCL 定位
│   ├── navigation/                # 二维规划、目标执行、速度门控
│   ├── gripper_control/           # 共用 TacCap 夹爪接口与调试页
│   └── workbench/                 # 连接、控制、地图、遥操、本地三维模型
├── scripts/
│   ├── pico4/                     # 头显接收、安装、预览
│   │   └── fairino/               # 遥操、插值、Home、清错、测量
│   └── run_diagnostics.sh         # 离线诊断入口
├── src/lerobot/                    # PICO/双手柄接入和 SDK 绑定
├── models/                        # 运动学 URDF、底盘和手腕网格
├── data/                          # 双雷达扫描与故障样例
├── tools/                         # 网络、机器人状态、SSH 工具
├── diagnostics/                   # 雷达与电池专项诊断代码
├── vendor/                        # 厂商运行库、头文件和版本信息
├── umi/                           # main 引入的官方 TacCap SDK 与验证脚本
├── tests/                         # 离线验证入口与记录
└── docs/                          # 安装、功能、网络、故障与模型说明
```

## 3. 控制能力

### 底盘

W/S 前进后退，A/D 横移，J/L 自转，支持组合键。启动先回正四个转向轴，再使能八轴；松键发送零速度。方向以机器人自身为准。默认平移 0.06 m/s、自转 0.10 rad/s，可在界面调整。详见 [底盘模块](../apps/fairino_keyboard/README.md)。

### 单关节和身体

左臂 J1–J7，右臂 J8–J14，J15 头部，J16 腰旋转，J17 侧倾，J18–J20 折叠机构。单轴窗口支持角度步进、绝对角度输入和计划速度调整。

身体窗口支持高中低、升降、前倾、侧倾和腰旋转。模型两段长度 360/380 mm；前倾 0–45°，腰旋转 ±90°，侧倾 ±15°且仅在高度≥90%、前倾≤5°时开放。这些是程序软范围。竖直参考已保存到 [body_config.json](../apps/fairino_upper_probe/body_control/body_config.json)，来源为用户声明的胸部姿态，并非 IMU 重力测量。几何标定及联动实测范围见 [身体说明](../apps/fairino_upper_probe/body_control/README.md)。

### TCP 键控

十二键连续控制法兰中心 TCP 的 6D 位置和姿态：W/S、A/D、R/F 控制 XYZ，I/K、J/L、U/O 控制绕 XYZ 旋转。采用统一胸部坐标 X 前、Y 左、Z 上，左右臂按键含义一致。厂家 FK/IK 与固定法兰偏移 `[-106,0,0] mm` 已接入。胸部倾斜后坐标轴随之倾斜。详见 [TCP 模块](../apps/fairino_tcp_probe/README.md)。

### PICO 双臂遥操

PICO 经 Wi-Fi 到电脑；电脑映射、灵敏度和冻结处理后，先做 TCP 位移线性插值／姿态 SLERP，再做厂家 IK，经有线 SSH 交给机器人 ROS 控制器执行单点位置保持。

`bash run.sh vr` 指定 450 Hz 插值/IK/下发、500 Hz 接收轮询、100 Hz 回传、12 ms 缓冲。`pico fairino` 原始入口默认 90/200/100 Hz。实际频率以日志为准。机器人端没有额外的 30 ms 关节追赶段；Home 使用单独的关节空间五次时间曲线。

| 操作 | 行为 |
|---|---|
| 右手柄／左手柄 | 默认镜像控制机器人左臂／右臂；第一人称同侧控制 |
| Grip 握住／松开 | 相对跟随／停止并保持 |
| A/X | 按住冻结旋转 |
| B/Y | 按住冻结位移 |
| 同时按两键 | 冻结两个分量，松开不补走 |
| 左手 X/Y 双击 | X 降低、Y 提高双臂灵敏度 0.25 / 0.5 / 1；长按仍冻结 |
| 左摇杆上下/左右（需勾选底盘） | 第一人称按机器人自身方向平移；默认面对面模式前后和左右都反向，回中停车 |
| 右摇杆左右（需勾选底盘） | 车身左转/右转；单独拨动时原地旋转 |
| 左摇杆按压 | 记录头显水平朝向，校准双臂遥操正前方 |
| 空格 / 工作台「暂停 / 保持」 | 暂停 |
| 右摇杆按压 | 回 Home，再按中止 |
| Trigger（需勾选夹爪遥操） | 连续开度 `1 - 按压量`，与同手柄控制的手臂对应 |
| 右摇杆上下（需勾选身体预设升降） | 持续推1秒：上到高位100%，下到下位66.7%；30°/s，回中继续到位；无需握 Grip |
| Esc/Q/Ctrl+C | 退出并请求上半身及本会话启用的底盘、夹爪下使能 |

默认启动先回双臂 Home，Home 期间 J15–J20 保持；可加 `--no-auto-home` 跳过自动回程。夹爪和身体升降默认关闭，在 PICO 页勾选后再启动，或使用 `bash run.sh vr --grippers --body-lift`。夹爪调试与遥操共享 SDK 会话实现，身体升降复用已有几何模型和高低位标定，双臂和升降合并到同一个二十轴控制实例。升降每次长推只触发一次，已到目标不动，完成后需回中重备；暂停、Home和断流会取消，恢复后不续跑。下推选择下位66.7%，较原50%向高位提高原预设行程的1/3（当前标定约70.9 mm）；从更低处明确触发时会升到下位，启动本身保持原姿态。模型关节范围、厂家逆解检查、急停、硬件故障及断流检查继续生效。详见 [当前 PICO 功能](../scripts/pico4/README.md)。

校准前开启头显 Head / Controller Tracking / Send，松开两侧 Grip、两根摇杆回中，等机器人停稳后平视希望的双臂遥操正前方，按下物理左手柄摇杆。启用底盘时还会检查底盘停止。校准本身不产生运动，释放摇杆按键后重新握住 Grip 才开始新的跟随；失败仍保持暂停，显示原因并保留上次有效校准。校准保持镜像／第一人称模式及左右手路由，不改变底盘的机器人坐标映射；正常转头、暂停或松开 Grip 不清除校准，退出会话后失效。

底盘也是独立可选项：PICO 页勾选「同时启动底盘 · 回正并使能」，或 `bash run.sh vr --chassis`。
PICO 页「遥操方式」可选第一人称，独立入口为 `bash run.sh vr --mode first_person`；运行中不能切换。
两种界面模式的右杆旋转方向一致，不随头显转头改变。夹爪安装绑定已调整为左爪 SN `TCGU01A28Z0018s`、右爪 SN `TCGU01A28Z0015s`，手柄 Trigger 跟随其控制的手臂。
默认最大速度 0.06 m/s、0.10 rad/s，启动与暂停后需摇杆回中；无需 Grip。
两杆可组合平移和旋转，右摇杆上下仍用于身体升降；双击灵敏度只影响双臂，不改底盘速度。
底盘复用独立键控的 worker、同一厂家控制器及里程计生命周期，通信在线程中处理；两种入口互斥占用。
暂停/Home/输入陈旧时发送零速度并保持使能，退出时确认下使能。双击按第二次短按松开识别，
不会将长按冻结当作调档，但短按期间也会短暂冻结该分量。

### TacCap / XTac 夹爪

使用 main 分支引入的官方 TacCap SDK，上半身现有 `/home/fairino/umi/.venv` 负责串口控制，电脑负责界面。按 SDK Left/Right 的 Follower 身份识别，也可明确指定固件 SN；缺少的一侧灰色且不发送命令。连接只读；各自显式使能后，可设置连续开度、张开/闭合、保持和下使能。实测开度、力矩和温度回传到界面。

默认 1.1 Nm、0.25 rad/s，按实际电机规格和固件包络校验。启动以当前位置播种，不默认张开或闭合；暂停保持使能，退出请求下使能。夹爪调试、PICO 夹爪控制互斥，SDK 网络和串口处理不占用双臂高频循环。详见 [调试说明](../apps/gripper_control/README.md) 和 [SDK 原始记录](../umi/README.md)。

### 清错与开机检查

开机/重启后可能出现全局 `0x0E10FF01`、关节 `J15=30`。`30` 为各轴十进制错误码，现有故障表归为 EtherCAT 通信类故障，具体原因结合当次反馈判断。

```bash
bash run.sh errors
# 有故障时：退出控制程序，确认静止、急停释放；允许部分轴仍使能
bash run.sh errors --execute
bash run.sh errors
```

脚本通过厂家 `reseterror()` 单次复位，先上半身后底盘。允许部分轴仍使能：先结束运动控制并确认静止，底盘停用已知的 eight_dof 控制器并暂停里程计；再单次清错，确认故障归零后按需下使能。最终观察 5 秒，末尾至少 2 秒故障为零、静止且全部下使能才确认完成。它不发送使能或运动目标；失败显示所处阶段，不重复复位。集成维护页、`errors` 和旧 `reset-upper` 入口共用实现。真实历史样例在 [startup-fault30-reset.json](../data/diagnostics/startup-fault30-reset.json)，操作细节见 [故障排查](故障排查.md)。

### 雷达及离线诊断

`bash run.sh lidar` 显示前后两路激光；`diagnostics geometry` 分析内置底盘网格的雷达外壳中心，`diagnostics lidar` 使用内置扫描样例完成配准和验证，`diagnostics wrist` 绘制内置手腕模型。详见 [诊断入口](../diagnostics/README.md)、[雷达与模型](雷达与模型.md)。

## 5. 验证与能力边界

2026-10-22 合并地图、定位、导航与相关修复，并同步原工作目录的 PICO 头显朝向校准后，运行 `bash run.sh test`，共 **637 项全部通过**：底盘 80、单轴 64、身体 20、TCP 50、地图/定位 42、导航 46、工作台 58、夹爪 48、VR/清错 225、PICO 预览 4。另以假数据完成本机 GTK 地图/定位/导航面板实例化与按钮状态检查，没有连接机器人。旧安装验证记录见 [验证结果](../验证结果.json) 和 [测试记录](../tests/离线测试记录.txt)，其中数字为当时版本。离线测试不代替真机动作验证。

当前底盘已统一到厂家 `eight_dof_chassis_controller`，关闭开机自动使能；默认不启动建图。里程计采用原始轮速直通 `/odom` 与地面 TF，不运行 EKF。独立 SLAM 扫描筛选修复已部署，支持平移和原地转向取帧；界面以成功雷达匹配监测实际更新。

历史地图 `archive-20261018-212121-029419` 包含 145 个有效扫描，栅格范围约 14.05 × 20.15 m，使用的是修正前外参。后续应重新建图，另存、结束建图后在地图库明确选用新地图；保存不自动选择默认底图。本次本地同步未读取机器人当前地图库，也未替用户选择或覆盖地图。

2026-10-19 的历史部署记录确认两个雷达固定 TF 已按车身 X 前、Y 左统一坐标，yaw 修正 90°；2026-10-22 同步了对应本地 URDF 与记录。此前轮速与 SLAM 轨迹约 88° 的最佳拟合偏差仍需用新地图和运动测试复核，不能仅凭外参修改宣称实测误差已经消除。详见 [雷达与模型](雷达与模型.md)。

AMCL 定位和二维 Nav2 导航已集成到“建图与底盘”页，独立命令行入口保留。正常底盘退出时，只有零速度发送、下使能确认及反馈健康均满足，才保留厂家控制器的里程计测量；异常退出继续停用。导航采用分阶段准备与激活、固定低速和断流保护，当前只覆盖底盘二维轮廓，不包含伸出的双臂。来源电脑有较早版本部署及服务检查记录，最新连续执行参数仍待机器人端更新；本次只同步本地，没有部署、使能或执行运动。实际定位、连续行驶、避障及到点精度仍待联调，部署与使用见 [导航说明](../apps/navigation/README.md)。

电池模块提供串口/协议诊断，尚未形成确认可用的电量接口；力控拖动、灵巧手控制、全身世界坐标控制和完整数据集录制尚未集成为已验证功能。雷达机械外壳位置及软件 TF 参数本身也不等于完成实测标定。
